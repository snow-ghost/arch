# План версии 0.1

Дата среза: 19 августа 2026 года.

## Цель

Версия 0.1 должна давать кодовому агенту воспроизводимый алгоритм архитектурного надзора. Алгоритм ищет существующее поведение, проверяет зависимости и API, связывает структурный сигнал с конкретным вредом, строит проверяемое представление затронутой архитектуры, сравнивает два снимка в согласованном масштабе и выбирает минимальное исправление.

## Границы

В состав версии входят:

- один portable Agent Skill arch;
- метаданные для Codex, Claude Code и Cursor;
- документированная установка для OpenCode;
- основной workflow и условно загружаемые справочники;
- evidence-backed архитектурные представления с выбором вида и масштаба;
- сравнение commit, branch, release или каталогов с разделением структурного изменения и conformance regression;
- многоязычные профили для Python, JavaScript и TypeScript, Go, Rust, JVM, .NET, C и C++;
- структурные тесты пакета;
- 21 eval-кейс для парного сравнения;
- blind A/B harness и rubric;
- первичные и научные источники.

Версия не включает собственный универсальный linter, индексатор репозитория или менеджер зависимостей. Скилл использует инструменты проекта и предлагает новый анализатор только для повторяемого значимого правила.

## Принятые решения

### Evidence-first вместо каталога запретов

Наличие switch, regex, clone, старой версии или высокой метрики запускает проверку. Finding требует местоположение, доказательство, механизм вреда, минимальную коррекцию и проверку.

### Reuse ladder

Порядок поиска: репозиторий, стандартная библиотека, уже принятая зависимость, проверенная внешняя зависимость, локальная реализация. Порядок не отменяет проверку семантики и полной стоимости владения.

### Языковые профили

Общий workflow не навязывает объектные паттерны всем языкам. Exhaustive match в Rust и небольшой switch в Go могут быть предпочтительнее runtime-регистрации. C и C++ требуют проверки ABI и build matrix. Динамические экосистемы чаще нуждаются в type-aware проверке deprecated API.

### Метрики как triage

Версия использует дельты сложности, дублирования, циклов, поверхности API и зависимостей. Универсальный composite score отсутствует. Quality gate требует локальной причинной связи и воспроизводимой конфигурации.

### Сравнение изменения и соответствия

Режим сравнения разрешает baseline и target до неизменяемых идентификаторов, фиксирует range semantics и строит обе модели с одинаковыми scope, viewpoint, zoom и analyzer configuration. Результат отдельно называет масштаб изменения и статус соответствия заявленным ADR, dependency rules, contracts или исключениям. File churn, переименование и release number не используются как процент архитектурной деградации.

### Представления по вопросу и масштабу

Скилл выбирает context, component, dependency, sequence, DFD, process, state, ownership, deployment или IDEF0 по проверяемому вопросу. Узлы объединяют код по подтверждённой ответственности или границе. Evidence index связывает элементы с файлами, symbols, configuration, tests и runtime traces. As-is, inferred, unknown и to-be не смешиваются. Для локальной конструкции скилл может отказаться от диаграммы.

### Progressive disclosure

SKILL.md содержит только обязательный алгоритм. Детальные методики, источники и инструменты находятся в references. Это ограничивает контекст и снижает риск конфликтующей guidance.

## Критерии готовности

- Skill validator принимает структуру и frontmatter.
- Plugin validator принимает .codex-plugin/plugin.json.
- Все относительные ссылки SKILL.md существуют.
- Тесты проверяют component и sequence views, DFD, отказ от лишней диаграммы и неизвестные dynamic edges.
- Тесты сравнения проверяют явную регрессию границы, rename без логического изменения и неполный dynamic plugin graph.
- Манифесты имеют одинаковые name, version, license и skills path.
- Тесты проверяют три eval-маршрута и не менее восьми языковых контекстов.
- Dry-run создаёт manifest, skill digest и обе пары условий.
- Полный офлайн round-trip проверяет generation, blinding и scoring.
- Русскоязычные документы проходят расширенный технический lint с разобранными предупреждениями.
- Репозиторий опубликован в snow-ghost/arch и доступен для установки.

## Отложенная работа

### Независимая поведенческая оценка

Два многократных прогона baseline и arch на фиксированной модели не показали общего прироста. Второй прогон охватил действовавшие тогда 18 кейсов и восьмимерную rubric: четыре architecture-view кейса дали +0,67, прежние 14 кейсов — −0,14, общая дельта составила +0,04. Три новых comparison-кейса ещё не запускались с моделью. Кейсы и skill разрабатывались на открытом наборе, поэтому этот результат относится к tuning, а не к независимой проверке. Следующая версия требует скрытого набора или executable fixtures, независимого human spot-check и чистых профилей.

### Runtime fixtures

Текущие кейсы оценивают решение и план проверки. Следующая версия может добавить небольшие executable repositories с детерминированными тестами для части языков. Такой набор потребует фиксированных toolchains и отдельного учёта стоимости CI.

### Обновление источников

Статус библиотек, команд и моделей меняется. При изменении language-tooling.md следует сверять официальную документацию и дату среза. Исследовательские preprint-результаты требуют повторной проверки после публикации рецензированной версии.
